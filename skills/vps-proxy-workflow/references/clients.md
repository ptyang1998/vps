# 客户端接入、DNS 与规则

## 1. 本机导入

检查客户端与核心版本、当前配置来源、实际端口、系统代理、TUN、自启动及已有订阅。备份本机自己的配置与相关状态，核对哈希；含凭据的备份使用受限权限保存。

以独立本地配置导入新节点，保留原有订阅。节点文件、原始 URI 和完整客户端配置是不同导入对象。逐项核对协议参数，使用当前核心检查器验证后，再激活配置。

不要照抄其他电脑的本地代理端口、控制 API 端口或组名。使用实际监听验证，避免误走旧订阅、环境代理或另一代理进程。

系统代理仅覆盖遵守它的应用；TUN 涉及路由、DNS 与系统权限。按用户需求选择覆盖方式，现状已满足目标时保留它。开机启动未启用时，在交接中说明需要手动启动客户端。

## 2. DNS 分流

把域名查询使用的解析器、解析器连接的出站路径、节点域名的引导解析与最终业务路由分开判断。

适用于国内直连、其他代理需求的示意设计：国内域名由直连国内 DoH 处理，海外域名的 DoH 连接通过指定代理；DIRECT 出口按需要使用独立解析器，避免解析与路由绕行。按实际需求配置，不把地域分流强加给所有使用者。

Mihomo 的相关字段包括 `nameserver-policy`、`direct-nameserver`、`direct-nameserver-follow-policy` 和 `proxy-server-nameserver`；缓存算法与 `prefer-h3` 属于可以单独对照的参数。通过代理访问 DNS 时，节点域名还需要避免引导解析循环。[Mihomo DNS 官方文档](https://wiki.metacubex.one/config/dns/)

GUI 可能合并或覆盖订阅 DNS。尽量只调整本次配置的覆盖行为，再核对最终运行核心。保留无关订阅的解析设置，避免为修复一个配置而改动全部订阅。

验证应覆盖国内和海外查询，并区分冷缓存与热缓存。A 记录成功不能单独证明 IPv6、UDP 或 DNS 泄漏测试通过。

## 3. 指定域名固定节点

仅当用户要求固定某些域名的出口时，先确认实际节点和规则位置，再使用后缀规则覆盖域名及子域名。例如以下是不可直接使用的结构片段：

```yaml
rules:
  - DOMAIN-SUFFIX,example.com,REPLACE_WITH_FIXED_NODE
```

`REPLACE_WITH_FIXED_NODE` 必须替换为当前配置中的实际节点或符合要求的固定策略。对“固定出口、无直连备用”的要求，检查直接引用及所有嵌套组，不引入 DIRECT、fallback、url-test 或负载均衡路径。规则按优先级匹配，应放在会覆盖它的一般规则之前。[Mihomo 规则官方文档](https://wiki.metacubex.one/config/rules/)

核验 DNS 连接策略、最终规则命中、客户端真实请求和出口。DoH 经指定节点不等于业务请求已固定；仅看到配置文件中的规则也不足以验收。

用户撤销规则时，精确移除本次域名规则及对应 DNS 例外，保留其他内容，重新激活并检查实际核心。只在配置没有后续合法修改时使用整份旧备份覆盖；否则按差异撤销。静态导入其他设备的文件需单独同步。

## 4. Android / iPhone / Mac

生成目标客户端支持的配置，去除桌面专属监听、控制和系统字段，保留协议与 TLS 验证。不要为方便导入把完整凭据送到公共订阅转换网站。

Clash Meta for Android 的文件配置与节点 URI 使用各自入口；导入后选择配置，用户确认系统 VPN 权限，再检查规则模式和节点选择。

Shadowrocket 的字段、TUN/代理类型、包括所有网络和全局路由菜单需要按当前设备版本核对。不能把其他操作系统的菜单名称直接作为已生效事实，也不能仅由开启开关推断所有流量已覆盖。

每台设备分别验证 HTTPS、出口、目标分流及常用应用。桌面核心语法检查只能证明其兼容范围，移动端没有实机测试时交付为“已准备，待实机验证”。

## 5. 旧代理冲突：仅在任务需要时检查

逐项判断实际用途与优先级，不能把“存在配置”当作冲突：

| 检查项 | 判断要点 |
| --- | --- |
| 系统代理 / PAC / TUN | 当前生效者、真实监听、路由和 DNS 接管范围 |
| 环境变量 | 进程、用户和系统作用域的 HTTP_PROXY / HTTPS_PROXY / ALL_PROXY / NO_PROXY，以及大小写变体 |
| shell 启动文件 | 是否写入失效地址；修改后应用需重启进程或重新载入 |
| npm / Git / Homebrew | 工具配置来源、环境继承和项目级覆盖，保留仍在使用的代理 |
| 目标应用 | 独立代理、启动环境、登录会话与实际业务连接 |

修改前列出确切位置和影响并备份；仅处理有证据失效或冲突的项。读取配置避免回显带认证信息的 URL、令牌或完整环境。修改后使用用户实际客户端验收，独立测试程序成功不代表该应用成功。
