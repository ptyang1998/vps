# 服务器部署与证书维护

本文件适用于新部署或明确需要服务端维护的任务。已有节点接入新设备时，先读取客户端参考，不默认申请新证书、轮换凭据或重启服务器。

## 1. 现状、备份与访问

记录系统与架构、可用资源、现有监听、服务管理方式、证书来源、计量周期和可用恢复入口。真实地址、账户、到期账单和私密路径仅保存在本地受限记录中。

维护访问使用当前有效授权。临时 SSH 授权应限定本次需要的能力；记录精确新增项，完成后只撤销自己的授权，保留其他维护者的公钥。已有管理员凭据由用户通过受支持的私密方式使用，不写进脚本、仓库或聊天回显。

备份覆盖本次将修改的配置、服务单元、证书部署路径及必要元数据，验证复制结果。不要以重装、全局清空防火墙或替换全部授权文件作为常规起点。

## 2. 协议选择与失败边界

VLESS + TCP + 标准 TLS 是适用于兼容客户端的一条实施路径。WireGuard、REALITY 等方案按明确需求选择，不把单次失败或一次成功推广成所有网络的结论。

按层测试：监听与进程 → TCP 可达 → TLS/传输握手 → 客户端认证 → 代理访问。必要时比较服务端本机回环与远端测试：本机也失败时，优先排查实现、参数和兼容性，不能只归因于跨境链路。

更换目标、指纹或实现应有新证据；在有限的诊断组合仍失败后，停止临时公网服务，保留日志摘要，再在授权范围内选择替代路径。

标准 TLS 的 VLESS 字段以当前服务端及客户端文档为准；特别核对 ID、传输、安全层、SNI/SAN、ALPN、flow 和双方兼容性。不要从不相关配置复制 Vision 或 REALITY 字段。[Xray VLESS 官方配置](https://xtls.github.io/en/config/inbounds/vless.html)

## 3. 服务实现

- 从官方发行源获取与系统架构匹配的程序，核对发布校验信息。历史下载哈希只对应当时的具体文件。
- 使用专用服务账户和受限配置权限，以系统服务管理进程，保存启动和重载方式。
- 若本任务需要限制代理访问服务端内网、回环或链路本地资源，依据当前路由语法实施并验证，保留正常管理访问。
- 仅开放所需服务入口；服务器代理部署与系统转发/NAT 是不同实现，不把二者混用。
- 客户端 ID 按设备撤销需求分配。共用 ID 无法按设备独立撤销，导出文件时说明是否共用已有凭据。

提交配置前运行对应程序的配置检查。激活失败则恢复本次修改，不覆盖其他服务或持续重启已知失败的配置。

## 4. TLS 与证书续期

先确定客户端实际连接标识，再申请相符的 DNS 或 IP 证书。检查可信证书链、SAN、有效期、系统时间和私钥读取权限；服务端私钥无需交付客户端。

Let's Encrypt 提供有效期为 160 小时的短期 IP 证书，因此选用此路径时需要可靠的自动续期。该服务的支持范围和 ACME 客户端参数应在实施时核对。[Let's Encrypt 官方说明](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)

申请公开证书会涉及证书透明度记录，在申请前明确这项影响。证书签发可能需要接受服务条款，应遵守当前工具和用户授权流程。

实施顺序：

1. 先在测试环境验证挑战方式和客户端兼容性，再申请正式证书。
2. 为续期配置独立定时任务和部署钩子，私钥仅授予必要的服务读取权限。
3. 使用 HTTP-01 standalone 时，核对验证端口外部可达、占用情况及失败后的释放；不要假定所有挑战都使用同一端口。
4. 更新成功后，按服务支持方式部署并重载/重启自己的服务。
5. 验证续期模拟、部署钩子及客户端新连接，记录测试与真实续期的区别。

保留最近成功记录与失败日志，安排短于证书有效期且留有故障修复余量的检查周期。正常续期应继续使用可信链和身份匹配，不固定首张短期证书指纹。证书续期不等于软件升级。

## 5. 收尾与恢复

记录修改文件、服务状态、证书验证、代理访问和恢复方式；配置与密钥继续私密保存。撤销临时授权后，用不新增持久访问的方式验证撤销结果。

未实际重启时，把开机配置记为“已保存，重启后待验证”。下次维护先只读核验当前状态，避免因旧交接记录重复写入配置。
